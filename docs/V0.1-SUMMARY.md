# V0.1 技术文档

v0.1 是初始版本，搭起扩展骨架：注册一个命令，遍历 Notebook 的 Markdown 单元格，调 OpenAI 翻译，写回。依赖只有 VSCode API 和 Node 内置模块，不引第三方运行时库。

## 文件结构

```
src/
├── extension.ts    扩展入口，命令注册和翻译主循环
├── translator.ts   Translator 接口 + Mock/OpenAI 实现
└── utils.ts        hasChinese
```

## 实现的功能

- 命令 `ipynbTranslator.translateMarkdownEnToZh` 翻译当前 Notebook 的 Markdown 单元格。
- `hasChinese` 检测含中文的单元格并跳过，空白单元格也跳过。
- 两个翻译器：`MockTranslator`（原文前加 `[模拟翻译]` 标记，调试用）和 `OpenAITranslator`（调 Chat Completion API）。
- `withProgress` 显示进度条，`CancellationToken` 支持取消。
- 配置从 `ipynbTranslator.openai.*` 读。

## 关键 API 用法

读单元格和写回：

```typescript
const editor = vscode.window.activeNotebookEditor;
const cells = editor.notebook.getCells()
    .filter(c => c.kind === vscode.NotebookCellKind.Markup);

const edit = new vscode.WorkspaceEdit();
edit.replace(cell.document.uri, fullRange, translatedText);
await vscode.workspace.applyEdit(edit);
```

HTTP 请求用 Node 原生 `https` 模块，不引 axios 之类：

```typescript
const https = require('https');
// 封装成 Promise
```

OpenAI 请求温度 0.3，压低随机性保持翻译一致。系统 prompt 要求保留 Markdown 语法、代码块和变量名不翻译、LaTeX 不动。

## 设计取舍

零运行时依赖是刻意的。扩展只用到 `http`/`https`/`crypto` 几个内置模块，打包产物小，也不用担心供应链。代价是 HTTP 错误处理要自己写（这一层在 v0.3 换成了手写 helper，v0.4 换成了全局 `fetch`）。

类型检查开 `strict`。
