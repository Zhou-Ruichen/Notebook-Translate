# V0.4 技术文档：现代化与流式翻译

v0.4 把工程基线拉到当前 VSCode 扩展的标准：全局 `fetch` 替代手写 http、esbuild 单文件打包、Notebook API 迁到非废弃路径、翻译改成可中断的流式、Profile 管理换成 Webview 面板。

## 最低版本

`engines.vscode` 从 `^1.60.0` 提到 `^1.90.0`。全局 `fetch` 在扩展宿主里需要 Node 18，Node 18 对应 Electron 22，实测 `microsoft/vscode` 的 `devProperties.electron` 字段，VSCode 1.78 才第一次带上 Electron 22。地板定在 1.90 而不是 1.78，是因为 1.78 刚切 Node 18，靠太近容易踩到过渡版本的兼容问题。低于 1.90 装不上。

## 构建工具链

- TypeScript 4.9 → 5.x，`@types/node` 14 → 20，`@types/vscode` 1.60 → 1.90。
- 编译从 `tsc` 散落 `.js` 改成 esbuild 单文件 bundle：`esbuild src/extension.ts --bundle --external:vscode --format=cjs --platform=node --target=node20`。产物 `out/extension.js` 约 47KB。
- `tsc` 保留为类型检查器（`npm run typecheck`，`--noEmit`），esbuild 只转译不查类型。
- `.vscodeignore` 倒置成白名单，`.vsix` 只含 bundle、`media/`、README、LICENSE、package.json（共 7 个文件）。

## HTTP 层：fetch 重写

删掉了 `translator.ts` 里两个手写的 http/https 请求函数，三家翻译器（OpenAI、Ollama、百度）统一走全局 `fetch`，封装在 `httpFetch(url, init)` 里。

错误契约是这次重写的约束点：`extension.ts` 的 `_performTest` 用 `errorMessage.includes('401')`、`includes('ECONNREFUSED')`、`includes('连接')` 这种字符串匹配来分类错误。fetch 的行为和手写 http 不一样——它只在网络层失败时抛，HTTP 错误码不抛。所以 `httpFetch` 显式重建这些子串：

- 非 2xx 抛 `HTTP ${status}: ${body}`，和旧的 `HTTP ${statusCode}: ${data}` 逐字节一致，`includes('401')` 仍命中。
- 网络失败从 `error.cause` 取 `code`（形如 `ECONNREFUSED`）拼进消息，让 Ollama 的 `includes('ECONNREFUSED')` 分支继续工作。

这条契约有测试锁：`httpFetch` 的四种场景（401、ECONNREFUSED、200、5xx）各有一个断言检查消息子串。

## Notebook API 迁移

翻译主循环 `translateNotebookMarkdown` 里替换了三个符号：

1. `notebook.getCells()` → `notebook.cellCount` + `notebook.cellAt(i)`。`getCells()` 在新类型里标了废弃。
2. 单元格写回从 `WorkspaceEdit.replace(cell.document.uri, fullRange, text)` 改成 `NotebookEdit.replaceCells`：
   ```typescript
   const newCell = new vscode.NotebookCellData(
       vscode.NotebookCellKind.Markup, formattedText, 'markdown');
   edit.set(notebook.uri, [
       vscode.NotebookEdit.replaceCells(
           new vscode.NotebookRange(cell.index, cell.index + 1), [newCell])]);
   await vscode.workspace.applyEdit(edit);
   ```
   用 `cell.index`（notebook 内真实索引，不是过滤后的数组位置）。一次 `replaceCells` 是一次原子编辑，撤销时一个单元格一步回退。
3. `cell.kind === vscode.NotebookCellKind.Markup` 没动——它本来就是现代枚举名，不需要迁移。

`activeNotebookEditor` 没改。它在新类型里没有 `@deprecated` 标记，换 `visibleNotebookEditors` 是无意义的改动，还会改变"哪个编辑器算活动"的语义。

顺手修了一个潜在 bug：无 Profile 时点击"创建配置"调用的是未注册的 `ipynbTranslator.addProfile` 命令，会失败。改成调用已注册的 `manageProfiles`。

## 流式翻译

这是 v0.4 的主要功能变化。OpenAI 和 Ollama 的翻译改成流式，百度保持请求/响应。

接口加了一个可选方法：

```typescript
export interface Translator {
    translate(text: string): Promise<string>;
    translateStream?(text: string, onToken: (chunk: string) => void,
                     signal?: AbortSignal): Promise<string>;
}
```

用 callback 而不是 AsyncGenerator，因为调用方既要增量 token（更新进度）又要最终完整串（缓存、格式化），callback 直接返回最终串比 generator 重装配简单。`BaiduTranslator` 不实现 `translateStream`，调用方用 `translator.translateStream` 是否存在判断走哪条路。

两家协议：

- **OpenAI**：`/chat/completions` 加 `stream: true`，响应是 SSE。每行 `data: {json}`，`choices[0].delta.content` 是片段，`data: [DONE]` 结束。
- **Ollama**：`/api/chat` 加 `stream: true`，响应是 ndjson。每行一个 JSON，`message.content` 是片段，`done: true` 结束。

两家共用 `readLines(body, onLine, signal)` 读流：从 `response.body.getReader()` 读 chunk，`TextDecoder` 解码，按换行符切，缓冲跨 chunk 的不完整行。结束时调 `decoder.decode()`（无参）冲刷 decoder 内部残留的多字节序列，避免流尾切在 UTF-8 多字节边界时丢字符。

写回策略：流式期间 `onToken` 只更新进度条文案，不写单元格（不做逐 token 预览，避免闪烁和 undo 抖动）。流结束后用 `formatTranslation` 套上双语包裹，一次 `replaceCells` 写回。

取消：`withProgress` 的 `CancellationToken` 接到一个 `AbortController`，`token.onCancellationRequested` 触发 `abortController.abort()`。signal 传进 `fetch(url, { signal })`，请求中断，`getReader().read()` 抛 `AbortError`，translator 转成 `CancelledError`。循环捕获后退出，已译单元格保留。

空结果保护：流式累积的 `result` 如果清洗 `<think>` 后为空，`validateStreamResult` 抛错（区分"只有推理链"和"模型没返回内容"两种情况），不返回空串。否则空串会被 `replaceCells` 写进单元格，原文丢失，还会被缓存。这条路径有测试覆盖。

已知限制：百度的 `translate()` 不接 signal，取消时当前请求要等响应返回（含 1.1s QPS 等待）才停。让它接 signal 要改 `Translator` 接口和四个实现，收益只是少等 1-2 秒，没做。

## Webview Profile 面板

v0.3 的 Profile 管理是 `manageProfiles.ts` 里的多步 QuickPick/InputBox 向导。v0.4 换成活动栏里的 `WebviewView`（`ipynbTranslator` view container，`profilesView`）。原生 HTML/CSS/JS，不引框架，保持零运行时依赖。

### 文件结构

- `src/webview/profilePanel.ts`：`ProfilePanelProvider implements WebviewViewProvider`，处理 postMessage。
- `media/webview/profilePanel.js`：前端控制器（列表 + 表单）。
- `media/webview/profilePanel.css`：样式，用 `var(--vscode-*)` 主题变量适配明暗。
- `src/commands/manageProfiles.ts`：删除，逻辑迁入 provider。

### 消息协议

webview → host：

| type | 作用 |
|------|------|
| `getProfiles` | 拉取 profile 列表 |
| `saveProfile` | 新建或更新配置 |
| `saveKey` | 存密钥到 SecretStorage |
| `clearKey` | 清除已存密钥 |
| `deleteProfile` | 删配置 + 清密钥 |
| `activateProfile` | 激活并测连，失败回滚 |
| `testConnection` | 只测连，不改激活项 |

host → webview：`profiles`（列表，含 `hasKey: boolean`）、`activeProfileChanged`。

### 密钥不变量

webview 永远拿不到原始密钥。`getProfiles` 只返回 `hasKey: boolean`。新密钥进密码框，经 `saveKey` 存到钥匙串。已存密钥不回显，只能用「清除已存密钥」按钮删除。这条延续了 v0.3 在 `profileManager.ts` 建立的隔离。

provider 切换时 `updateProfile` 检测到 provider 类型变化会清掉旧密钥。密钥按 name 存、与 provider 无关，不清的话改名/改类型的 profile 会串用（比如百度 secretKey 被当 OpenAI key 读）。

### 连接测试

激活和测试都复用已注册的 `testConnection` 命令。v0.4 把它的返回值从 `boolean` 改成 `{ ok: boolean; error?: string }`，错误分类提到 `classifyTestError()`，silent 模式也执行，所以面板里激活失败能看到具体原因（401 / 连不上 / 模型未找到），不只是"连接失败"。

`testConnection` 现在优先用 `translateStream` 测连（openai/ollama），百度回退 `translate`。避免一种假绿灯：非流式请求能通、但流式 SSE 被代理截断的配置，旧版本会测连通过、翻译失败。

`handleTest` 临时切到目标 profile 测完再切回原来的 active，测试是只读操作，不改变当前激活项。`handleActivate` 失败时先试 `rollbackToPrevious`，回滚失败（首次激活、无历史）就恢复到激活前的 active，不让坏 profile 留作当前。

### CSP

CSP 的 script-src 用 nonce，JS 外链（`asWebviewUri`）不内联，避免开 `unsafe-eval`：

```
default-src 'none'; img-src ${cspSource} data:;
style-src ${cspSource} 'unsafe-inline'; script-src 'nonce-${nonce}';
```
